# 服务守护与采样异常通知

## 使用

- Agent 0.1.9 起默认每 30 秒检查 Hysteria 服务；服务为 inactive/failed 时尝试启动，失败后下一周期重试。独立检查循环不依赖面板连接。Agent 配置中的 `watchdog_interval_seconds` 可设置为 5–3600 秒，未配置或越界时使用 30 秒，修改后重启 Agent。
- 面板下发的停止操作会保存停止标记，Agent 重启也不会覆盖；通过面板启动或重启服务后重新启用恢复。直接使用系统命令停止服务会被视为需要恢复，请通过面板停止后再维护。
- 在「通知设置」填写 SMTP、发件邮箱和接收邮箱，开启 SMTP 与节点采样异常通知，设置连续无采样时间（30–86400 秒，默认 120 秒）。未开启 SMTP 时不会发送邮件。
- 面板每 15 秒检查一次已启用 Agent、未删除且已建立 Agent 记录的节点。以最新样本的采样时间判断，旧样本补传不算恢复；从未采样时以 Agent 安装时间（缺失则创建时间）开始计时。监控页显示「节点异常 · 采样中断」。
- 每次持续异常成功通知一次，状态持久保存；重新收到有效的新采样后解除去重，后续异常可再次通知。发送失败每 5 分钟重试。邮件只含节点名称、编号、检测时间和排查提示。

## 设置数据变更说明

- 目的与范围：复用 `system_settings` 保存通知开关、阈值和每节点通知状态；不改表结构、列或索引。
- 受影响键：`node_alert_enabled`（默认 true）、`node_alert_timeout_seconds`（默认 120）、`node_sample_alert_state_<节点编号>`（JSON：notified、retry_at）。
- 执行顺序：先备份数据库与运行包，更新面板和前端、Agent 发布产物，再启动面板。启动时按现有默认设置补齐流程幂等新增缺失键，不覆盖已有配置；节点状态按唯一 setting_key 执行 upsert。Agent 随现有心跳升级流程更新至 0.1.9。
- 回滚：停止新面板并恢复旧运行包、Agent；新增设置可保留，旧版忽略。若要撤销数据，先备份这些键后按精确键名清除。Agent 配置旁的 `.service-stopped` 文件记录运行意图，保留以便再次升级。
- 验证：单元测试覆盖边界时间、旧样本、首次采样等待、重复异常、恢复再异常、发送失败重试、主动停止与恢复；构建前端与 Linux 两种 Agent。上线后用测试节点中断采样超过阈值，核对邮件与恢复后的第二次告警；不要直接中断生产节点。
- 风险：面板自身停止时无法发信，恢复后检查仍然异常的节点；依赖面板/节点时钟准确。SMTP 接收成功与状态写入无法跨系统原子提交，进程在二者之间崩溃时可能重复通知；当前面板按单实例后台检查运行，多实例部署需要另加分布式任务互斥。邮件主题不含节点输入，正文不包含连接凭据。
